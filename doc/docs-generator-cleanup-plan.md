# Doc Generator Cleanup & Redesign Plan

## Background

An agent implemented a "document generator" feature (`generate-docs`,
`markdown-docs`, `pydoc` CLI commands) without asking, leaving the repo in an
uncommittable state: 6 fabricated ADRs written into the real `docs/adr/`
production directory, ~100 untracked generated files (`docs/api/*.md`,
`docs/pydoc/*.html`), a stray misplaced/duplicated file in `doc/`, `ruff
check` failures, a dead-code bug, a stale `AGENTS.md`, and zero test coverage
on the actual file-writing entry points. This plan cleans that up and lands a
smaller, correct, maintainable version of the feature.

## 1. Cleanup (delete-only, untracked, safe)

- Delete the 6 fake ADRs under `docs/adr/*.md` (LDAP auth, mobile platform,
  primary datastore, Python 3.11-vs-3.13, build-vs-buy, tool selection).
- Delete the stray
  `doc/…-choice-of-python-package-and-environment-manager copy.md`.
- Delete `docs/pydoc/` entirely (HTML output dropped per decision below).
- Delete the current stale `docs/api/*.md` (will be regenerated correctly in
  step 5).

## 2. Consolidate the command surface

- Merge `commands/generate_docs.py` + `commands/markdown_docs.py` into a
  single new module `commands/docs.py`, exposing one command:
  **`specmgr docs`** — no switches, always does both jobs:
  1. Writes `docs/api/*.md` (per-module Markdown API reference; committed to
     the repo for GitHub browsing — no regeneration step needed to view it).
  2. Writes `docs/GENERATED.md` (domain list, module docstrings, test count —
     replaces the content previously regex-spliced into `AGENTS.md`).
- Delete `commands/pydoc.py` and `tests/commands/test_pydoc.py` (HTML dropped
  — doesn't render usefully in GitHub's file browser and duplicates the
  Markdown output).
- Fix concrete bugs found during review:
  - `ruff check` failures: unused `indent` variable in the index generator, 2
    stray f-string prefixes.
  - Hardcoded `"python"` → `sys.executable` in the test-count subprocess
    call.
  - `--output` flag inconsistency in the old `generate_docs.py` (silently
    ignored unless exactly `"AGENTS.md"`) — moot once consolidated into the
    fixed-destination `docs` command.
- Update `cli.py` / `commands/__init__.py` registrations accordingly.
- Add tests exercising the actual `docs()` Typer entry point (the
  file-writing code path) via `tmp_path`, not just its private helpers —
  closing the coverage gap that let this ship broken.

## 3. De-risk `AGENTS.md`

- Replace `AGENTS.md`'s `## Generated Section` internals with a short,
  permanent, hand-written pointer to `docs/GENERATED.md` (e.g. *"See
  [`docs/GENERATED.md`](docs/GENERATED.md), auto-generated by `specmgr
  docs`."*). This file is never regex-edited again — eliminates the fragile
  splice logic that caused the duplicate-section bug found during review.
- Correct the stale "No `publish.yml` yet" line in the "CI / Release"
  section — `publish.yml` exists and has shipped `v0.1.0`, `v0.2.0`,
  `v0.2.1`.

## 4. Adopt `pre-commit`

- Add `pre-commit` to the `dev` extras group in `pyproject.toml`.
- Add root `.pre-commit-config.yaml`:
  - Official `ruff-pre-commit` hooks (format + lint) — same checks CI
    enforces, now caught before commit.
  - Local hook `specmgr-docs`: `uv run --frozen specmgr docs`, scoped to
    `src/**/*.py` changes. Standard formatter-hook UX: if it modifies
    `docs/api/`/`docs/GENERATED.md`, the hook reports "files were modified"
    and the commit stops so those files get staged and committed
    deliberately.
- Document the one-time `pre-commit install` step in `AGENTS.md`'s
  "Developer Commands" section.

## 5. CI backstop (confirmed: yes)

- Add a step to `.github/workflows/ci.yml` that regenerates docs into a
  temp/scratch location (or runs `specmgr docs` against a clean checkout
  copy) and fails the build if the result differs from what's committed —
  catches drift for anyone who bypassed or never installed the pre-commit
  hook (fork PRs, `--no-verify`, fresh clones).
- Explicitly **out of scope**: no `validate_adr` hook wiring in pre-commit or
  CI (confirmed) — stays a separately tracked gap per `AGENTS.md`.

## 6. Changelog & final regeneration

- `CHANGELOG.md [Unreleased] → Added`: the new `specmgr docs` command,
  `pre-commit` adoption + CI backstop, `docs/api/` committed-to-repo policy.
- Once code is fixed: run `specmgr docs` for real, run `pre-commit run
  --all-files` to validate the full loop end-to-end, then commit everything
  together — no `docs/pydoc/`, no fake ADRs, no leftover stray files.
