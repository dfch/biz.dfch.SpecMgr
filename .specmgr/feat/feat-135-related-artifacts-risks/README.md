# Feature: Replace Acceptance Criteria with Risks in Related Artifacts; Validate Cross-Reference Format

## Plan

### Overview

`req`, `gol`, `dec`, and `sop` all share an identical `## Related Artifacts` shape with four (five for `sop`) `### ` cross-reference sub-lists. One of them, `### Acceptance Criteria`, references an artifact type that was never implemented as a standalone domain -- acceptance criteria only exist as `AC-NNN` entries inside a `vcr` (Verification Case Record) document, and VCR already owns the correct, backward-only link (`## Verifies` -> `REQ`/`UC`). This feature removes that dead sub-list from all four domains, replaces it with a new `### Risks` cross-reference to `rsk`, and -- since none of these sub-lists have ever had any format validation -- adds a shared, enforced `"<TYPE> <uuid>: <title>"` format to every sub-list in all four domains, reusing the pattern already proven by `vcr`'s `## Verifies` and `sysrs`'s per-section cross-reference lists (extracted into a new shared `models/md` helper rather than duplicated a third/fourth time).

### Requirements

- REQ-001: `AcceptanceCriteria`/`acceptance_criteria` MUST be removed entirely from `RelatedArtifacts` in `req`, `gol`, `dec`, and `sop`.
- REQ-002: A new `Risks`/`risks` cross-reference sub-list (to `rsk`) MUST be added to `RelatedArtifacts` in `req`, `gol`, `dec`, and `sop`, in the slot `AcceptanceCriteria` occupied.
- REQ-003: `Goals`/`goals` MUST remain unchanged (present, in scope) in all four domains -- it is not added to `vcr`, and `rsk` getting its own `Related Artifacts` section is explicitly out of scope here.
- REQ-004: Every cross-reference sub-list item (`Requirements`, `Decisions`, `Goals`, `Risks`, and `sop`'s `Sops` self-reference) MUST be validated against a common format: `"<TYPE> <uuid>: <title>"` (space-separated, lowercase 8-4-4-4-12 hex UUID, full-line match), reusing a single shared validator rather than a fourth independent reimplementation.
- REQ-005: `Decisions` MUST accept only the `DEC` type tag (not `DEC|ADR`), since `adr` is slated for removal as an artifact type (issue #46).
- REQ-006: Every affected sub-list's items MUST support an optional trailing notes paragraph (`MarkdownListItemWithNotes`), mirroring `sysrs`'s existing shape.
- REQ-007: The shared validator/pattern logic MUST live in `models/md` (`_cross_reference.py`, imported directly by callers -- not re-exported from `models/md/__init__.py`, matching the `_ordering.py`/`_errors.py`/`_markdown.py` precedent), and `sysrs`/`vcr` MUST be refactored to reuse it instead of keeping their own independent, duplicated implementations.
- REQ-010: `req`/`gol`/`dec`/`sop`'s recurring `Requirements`/`Decisions`/`Goals`/`Risks` classes (byte-identical across all four domains today) MUST be built on shared `RequirementsBase`/`DecisionsBase`/`GoalsBase`/`RisksBase` classes added to `models/md/common_sections.py`, mirroring the `SourceBase`/RASCI precedent from `feat-29-dec-source-roles` -- each domain keeps only a thin, docstring-only subclass (no field redeclaration). `sop`'s `Sops` self-reference (no cross-domain twin) and `sysrs`/`vcr` (structurally heterogeneous placement under different H2 parents) are explicitly excluded from this base-class layer and stay function-only, unchanged from REQ-007.
- REQ-008: Packaged examples, templates, and create/update instructions for `req`/`gol`/`dec`/`sop` MUST be updated so none of them drift from the new schema (no stale Acceptance Criteria mentions, no unvalidated example bullets).
- REQ-009: The 14 real, on-disk REQ documents (`docs/req/*.md`) whose `### Goals` bullet currently uses the unvalidated `GOL-<uuid>` (dash) form MUST be migrated to the enforced `GOL <uuid>` (space) form via the generic `update` tool (`type="req"`) BEFORE the model change lands: the `update` tool's per-domain adapter re-parses the existing document first and converts a parse failure into a not-found error before any write, so once the `^GOL {uuid}: .+$` validator is live it can no longer rewrite the dash-form documents -- under today's unvalidated schema the space form already parses, so pre-migration is lossless.

### Design Notes

**Shared validator primitives (`models/md/_cross_reference.py`)**: new module exporting `UUID_PATTERN` (the shared lowercase 8-4-4-4-12 hex fragment, generalized from `sysrs`'s local `_UUID_PATTERN`), a pattern-builder for one or more type tags, and `validate_cross_reference_items(items, pattern)` (generalized from `sysrs`'s local `_validate_cross_reference_items`: `re.fullmatch` + `re.DOTALL`, a plain `ValueError` of the same shape -- actionability, i.e. field path, line, cause/fix hint, and domain + tool context, is added at the tool layer by feat-27's `wrap_tool_errors`, not by the helper itself). Like every other private (`_`-prefixed) shared helper in `models/md` (`_ordering.py`, `_errors.py`, `_markdown.py`), this module is **not** re-exported from `models/md/__init__.py` -- callers import it directly (`from ....models.md._cross_reference import ...`), matching the established convention rather than introducing a new one. `sysrs` and `vcr` are refactored to import from here instead of keeping independent copies; the docstring cross-references to the helper's old `sysrs` location in `rsk/models/v1/tara.py` (two places) and `general/models/dtais.py` (one place) are updated to point at `models/md`, and `vcr` keeps its module-level `_VERIFIES_PATTERN` name (built from the shared fragment) so `tests/vcr/models/v1/test_body.py`'s docstring reference stays accurate.

**Shared base classes (`models/md/common_sections.py`)**: `req`/`gol`/`dec`/`sop`'s `Requirements`/`Decisions`/`Goals`/`AcceptanceCriteria` classes are byte-for-byte identical today (same docstrings, same stale `Field(description=...)` example IDs), and adding `Risks` in the same shape to all four domains would just add a fifth quadruplicated class. Rather than repeat that, `RequirementsBase`/`DecisionsBase`/`GoalsBase`/`RisksBase` are added to `models/md/common_sections.py`, mirroring the `SourceBase`/RASCI precedent `feat-29-dec-source-roles` (issue #29) established for exactly this scenario. Since the pattern per role is identical across all four domains (`Requirements` is always `^REQ {uuid}: .+$` regardless of which domain it's in), each base class is a complete, ready-to-use class (`MarkdownSection3`, `items: list[MarkdownListItemWithNotes] = Field(min_length=1, ...)`, `field_validator` calling `validate_cross_reference_items`) -- simpler than `RolesAndResponsibilitiesBase`'s field-narrowing trick, since there is no per-domain item-subtype variance to narrow. Each domain keeps only a thin, docstring-only subclass (`class Requirements(RequirementsBase): """domain-specific docstring"""`), exactly like `req.Source`/`dec.Source` today. `@alias`'s default `SPACE_SEPARATED` heading match is derived from `cls.__name__` at parse time (confirmed by `common_sections.py`'s own documented mechanism), so a subclass named `Requirements`/`Decisions`/`Goals`/`Risks` matches its heading automatically with no `@alias` override needed. This base-class layer is deliberately scoped to `req`/`gol`/`dec`/`sop`'s four recurring roles only: `sop`'s `Sops` self-reference has no cross-domain twin (stays a plain inline `field_validator` call against `_cross_reference.py`'s primitives, same as before), and `sysrs`/`vcr` are excluded because their cross-reference sections sit under structurally different H2 parents with more contextual variance (e.g. `sysrs.Goals` under `## Business Context and Goals`) -- retrofitting them onto the same base classes would expand this feature's scope beyond the behavior-preserving refactor REQ-007 already promises.

**Per-domain model changes** (`req`, `gol`, `dec`, `sop`): remove `AcceptanceCriteria`/`acceptance_criteria` (class + `RelatedArtifacts` field + `__init__.py` export); add `Risks` (subclassing the new `RisksBase`) + `risks` field in the slot `AcceptanceCriteria` occupied; change `Requirements`/`Decisions`/`Goals` to subclass the new `RequirementsBase`/`DecisionsBase`/`GoalsBase` (dropping their own independent `items`/`field_validator` declarations in favor of the inherited ones); `sop`'s `Sops` self-ref keeps its own inline `field_validator` against `^SOP {uuid}: .+$` (no base class, per the scoping above). All these sub-lists' `items` type changes from `MarkdownListItem` to `MarkdownListItemWithNotes` (already imported in each of these files for `## Tags`) via the inherited base-class field. Every affected sub-list's docstring is reworded from the stale dash-form example IDs (e.g. `"REQ-9687: <title>"`) to the enforced format -- the shared `Field(description=...)` wording now lives once in each `*Base` class rather than four times, since those strings flow into the packaged `*_schema.json` copies and the generated API docs.

**Known, accepted limitation**: the new format constraint is invisible in the generated JSON Schema, since it's enforced via a Pydantic `field_validator` on a `@computed_field` (`MarkdownListItem.text`), not a schema-declared `Field(pattern=...)` string. This mirrors `vcr`/`sysrs`'s existing behavior and is not something this feature fixes.

**Migration (ordering is load-bearing)**: the 14 real `docs/req/*.md` documents (created for `feat-84-specmgr-sysrs`) currently populate `### Goals` with the unvalidated `GOL-<uuid>: <title>` (dash) form. They MUST be rewritten to `GOL <uuid>: <title>` (space) via the generic `update` tool (`type="req"`) -- not a manual file edit, and not `update_section` (an ADR-only tool) -- BEFORE the model change lands: the `update` tool's per-domain adapter re-parses the existing document first and converts a parse failure into the domain's not-found error before any write, so once the new `^GOL {uuid}: .+$` validator is active it would refuse to rewrite exactly these documents. Under today's unvalidated schema the space form already parses, so the pre-migration is lossless and the repo's own documents are never in a parse-broken window. No other real `req`/`gol`/`dec`/`sop` document on disk has populated `Related Artifacts` content (confirmed: no `docs/dec/` directory exists yet; `docs/gol/`, `docs/sop/` have none populated).

**Interactions with other work**: the enforced `SOP <uuid>` self-reference introduces the first schema-validated tag absent from `general/tools/_references.py`'s `REFERENCE_TYPES` vocabulary (feat-144-ref-artifact), so `list_references` skips such bullets until a future vocabulary extension -- recorded in Out Of Scope, not fixed here. Likewise, `Decisions` going DEC-only in the four domains (REQ-005, because `adr` is slated for removal per issue #46) while `sysrs` keeps `^(DEC|ADR)` is a deliberate, recorded asymmetry, not drift.
