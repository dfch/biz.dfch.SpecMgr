# Phase 120 Validation Run 3: Apache OFBiz (traditional enterprise application)

Task 120.100, validation run 3, one of the three architecture classes of QA 0.0340: a traditional enterprise application. Validation of the Architecture Model (TXT 30983f27, Draft 0.5) and the checklist matrix (TXT 23ded6d8, Draft 0.12) against Apache OFBiz. This is a validation of the catalogue, not a review of OFBiz. Ratings appear only where they test a catalogue rule. All paths below are paths in `apache/ofbiz-framework` at the baseline commit, unless another repository is named.

## 1. Scope

- System: Apache OFBiz, `apache/ofbiz-framework`, branch `trunk`, commit `cdea248bcfb61b7c5c0945b9113b8cf72f0bfee3` (2026-11-22T14:38:19Z). `VERSION` says `Trunk`. The plugin repository `apache/ofbiz-plugins` (branch `trunk`) was only listed, not read.
- Architecture class: traditional enterprise application. One JVM (`build.gradle` mainClass `org.apache.ofbiz.base.start.Start`) with embedded Tomcat, an entity engine and a service engine. 13 framework components (`framework/component-load.xml`) and 12 application components (`applications/component-load.xml`), 21 webapps in one Tomcat server. One relational database with three entity groups (main, olap, tenant) (`framework/entity/config/entityengine.xml`).
- Subject: a product (an open-source framework and application suite), not an installation. `SECURITY.md` assigns infrastructure, network exposure, logs, plugins and integrations to the deployer. VP06 and VP07 are therefore tested against the reference deployment of the project, `docker/examples/postgres-demo/docker-compose.yml`. See O-08.
- Review type used for the test: periodic health check (the product is in production use and released in branches; trunk is the baseline).
- Safety gate: not safety relevant. Justification: a general-purpose ERP for accounting, order, product, party and manufacturing data. It controls no equipment and supports business decisions without a direct safety consequence. Origin Inferred: the repository makes no statement about safety. An installation that plans production of safety-relevant goods with the manufacturing component must decide again (checklist 5.2, "software that influences decisions"). See O-08.
- Evidence sources: `README.md`, `SECURITY.md`, `DOCKER.adoc`, `Dockerfile`, `docker/`, `UPGRADING.md`, `applications/UPGRADING.md`, `build.gradle`, `settings.gradle`, `framework/*/ofbiz-component.xml`, `applications/*/ofbiz-component.xml`, `entityengine.xml`, `serviceengine.xml`, `framework/common/config/general.properties`, `framework/security/config/security.properties`, `framework/base/config/debug.properties`, `framework/start/.../start.properties`, `framework/catalina/ofbiz-component.xml`, all `*/entitydef/*.xml` (31 files), all `*/servicedef/*.xml` (128 files), `docs/asciidoc/developer-manual.adoc` (section Main systems only), `.github/workflows/`.
- Model: `workspace.dsl` in this folder. Checked with the Structurizr MCP (version as in QA 0.0500). `validate`: OK. `inspect` (workspace scope `softwaresystem`), first run: three errors, the two expected ones (no documentation, no decisions) and "The infrastructure node Docker postgres-demo/Docker host/Reverse proxy and firewall is disconnected". A Proposed relationship from the proxy to the server instance was added (O-13). Final `inspect` output:

```
["ERROR: The software system \"Apache OFBiz\" has containers, but is missing documentation.",
 "ERROR: The software system \"Apache OFBiz\" has containers, but is missing decisions."]
```
