    Here is the corresponding *Structurizr DSL* using a C4 Container-
    style architecture diagram. It represents the flow from Java backend
    error handling through OpenAPI validation and code generation to the
    React application.

    structurizr

    |workspace "API Error Handling Architecture" "End-to-end API error contract and client integration." {

        model {
            softwareSystem "Application" {

                container "Java Backend" "Java backend application" "Java" {
                    component "Exception Mapping" "Maps backend exceptions to standardized API errors."
                    component "RFC 9457 Problem" "Produces RFC 9457 Problem Details responses."
                    component "OpenAPI Contract" "Defines the API error contract."
                }

                container "OpenAPI Quality & Compatibility" "Validates and checks the OpenAPI contract." {
                    component "Spectral" "Lints the OpenAPI contract." "Spectral"
                    component "oasdiff" "Checks OpenAPI contract compatibility and breaking changes." "oasdiff"
                }

                container "OpenAPI Specification" "Validated OpenAPI specification." "OpenAPI" {
                }

                container "Code Generation" "Generates backend and frontend types from OpenAPI." {
                    component "openapi-generator" "Generates Java models." "openapi-generator"
                    component "Orval" "Generates frontend API schemas." "Orval"
                }

                container "React Application" "Frontend application." "React" {
                    component "Zod Schemas" "Runtime validation schemas for API errors." "Zod"
                    component "React Error Parser" "Parses RFC 9457 Problem Details responses."
                    component "Central Error Handler" "Centralizes API error handling."
                    component "Application UI" "Displays errors to application users."
                }
            }

            "Application.Java Backend".Exception Mapping -> "Application.Java Backend".RFC 9457 Problem
            "Application.Java Backend".RFC 9457 Problem -> "Application.Java Backend".OpenAPI Contract

            "Application.Java Backend".OpenAPI Contract -> "Application.OpenAPI Quality & Compatibility".Spectral
            "Application.Java Backend".OpenAPI Contract -> "Application.OpenAPI Quality & Compatibility".oasdiff

            "Application.OpenAPI Quality & Compatibility".Spectral -> "Application.OpenAPI Specification"
            "Application.OpenAPI Quality & Compatibility".oasdiff -> "Application.OpenAPI Specification"

            "Application.OpenAPI Specification" -> "Application.Code Generation".openapi-generator
            "Application.OpenAPI Specification" -> "Application.Code Generation".Orval

            "Application.Code Generation".openapi-generator -> "Application.Java Backend".RFC 9457 Problem
            "Application.Code Generation".Orval -> "Application.React Application".Zod Schemas

            "Application.React Application".Zod Schemas -> "Application.React Application".React Error Parser
            "Application.React Application".React Error Parser -> "Application.React Application".Central Error Handler
            "Application.React Application".Central Error Handler -> "Application.React Application".Application UI
        }

        views {
            component "Application.Java Backend" {
                include *
                autolayout lr
            }

            component "Application.OpenAPI Quality & Compatibility" {
                include *
                autolayout lr
            }

            component "Application.Code Generation" {
                include *
                autolayout lr
            }

            component "Application.React Application" {
                include *
                autolayout lr
            }

            styles {
                element "Component" {
                    background #1168bd
                    color #ffffff
                }
                element "Container" {
                    background #438dd5
                    color #ffffff
                }
            }
        }
    }
    |


          Architecture flow

     1. *Backend:* Java exceptions are mapped to RFC 9457 Problem Details.
     2. *Contract:* The OpenAPI contract describes the standardized
        error responses.
     3. *Validation:* Spectral performs linting, while oasdiff checks
        compatibility.
     4. *Specification:* A validated OpenAPI specification becomes the
        source of truth.
     5. *Code generation:*
          * openapi-generator generates Java models.
          * Orval generates frontend schemas.
     6. *Frontend:* Zod schemas validate errors, the React Error Parser
        normalizes them, and the Central Error Handler delivers them to
        the Application UI.

    *Important:* I would recommend treating the OpenAPI specification as
    the single source of truth and generating both Java models and
    frontend schemas from it. This avoids contract drift between backend
    and frontend.
